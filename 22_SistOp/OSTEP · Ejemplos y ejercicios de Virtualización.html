Cap. 5 · fork/wait/exec, redirección resuelto
  • fork: padre recibe PID del hijo, hijo recibe 0, error < 0; el orden padre/hijo no está determinado.
  • Con wait() el hijo termina antes de que siga el padre.
  • wc archivo.c > salida.txt: el hijo cierra stdout y abre el destino antes del exec (UNIX asigna el menor fd libre).
  • grep foo archivo | wc -l con pipe().

Cap. 6 · Limited Direct Execution resuelto

Flujo de una syscall: trap → nivel kernel, trap table (configurada al boot) → handler → return-from-trap. Con timer interrupt: el hardware guarda los regs de usuario en el kernel stack (guardado implícito) y swtch guarda los del kernel (explícito). Sin timer, un loop infinito monopoliza la CPU.

→ Práctico Ej. 11, 12(e)

tarea Medir el costo de una syscall y de un context switch (lmbench-style, con pipes entre dos procesos).
Cap. 7 ★ · Scheduling clásico resuelto (valores del libro)
  • 3 jobs de 10 s llegando juntos, FIFO: turnaround promedio = (10+20+30)/3 = 20.
  • Convoy: A=100, B=C=10, FIFO → (100+110+120)/3 = 110.
  • SJF sobre el mismo caso → (10+20+120)/3 = 50.
  • B y C llegan en t=10 (A ya corriendo): SJF no apropia (mal), STCF sí → turnaround promedio 50.
  • Response time: 3 jobs de 5 s, SJF → (0+5+10)/3 = 5; RR con slice 1 → (0+1+2)/3 = 1 (pero turnaround peor).

Con I/O: cada ráfaga de CPU es un "sub-job"; mientras A hace I/O corre B (overlap).

→ Práctico Ej. 13, 14, 16, 18

tarea scheduler.py con FIFO/SJF/STCF/RR: calcular a mano turnaround y response y verificar con -c; process-run.py para el overlap CPU/IO.
Cap. 8 · MLFQ resuelto

Reglas finales 1–5 (prioridad, RR en el mismo nivel, job nuevo arriba, baja al agotar el allotment sin importar los yields, boost cada S). Problemas que motivan cada regla: starvation → boost; gaming (I/O justo antes del quantum) → mejor contabilidad; cambio de comportamiento → boost. Configuración típica: quanta cortos arriba, largos abajo.

→ Práctico Ej. 17, 18(d)(e)

tarea mlfq.py: con 2–3 colas, trazar jobs de distinta duración, con y sin boost, con y sin gaming.
Cap. 9 · Proporcional resuelto

A=75 y B=25 tickets → 75 % / 25 % esperado (probabilístico en lottery). Stride: stride ∝ 1/tickets, corre el menor pass value, exacto pero requiere estado global. CFS: menor vruntime, slice = sched_latency / n (mínimo min_granularity), nice −20…19 cambia el peso.

El práctico no lo toma, pero podría aparecer como V/F.

tarea lottery.py y stride.py: ¿cómo mejora la fairness al crecer el tiempo de corrida?

Parte II · Memoria

Cap. 13–14 · Address space y API resuelto

Layout: código arriba de todo, heap crece hacia abajo, stack hacia arriba. int *x = malloc(sizeof(int)) son dos reservas: el puntero en el stack, el int en el heap. Errores típicos: olvidar reservar, poco espacio (sin +1 para \0), leak, free doble, free de puntero inválido, usar después de liberar. Herramientas: gdb, valgrind.

Cap. 15 · Base y bounds resuelto

Espacio de 4 KB cargado en 16 KB: virtual 0 → 16 KB; 1 KB → 17 KB; 3000 → 19384; 4400 → fault. El código 128: movl…, 132: addl…, 135: movl… muestra que cada fetch, load y store se traduce.

Cap. 16 · Segmentación resuelto

Tabla: Code 32K/2K, Heap 34K/3K, Stack 28K/2K. Virtual 100 (código) → 32868. Virtual 4200 (heap): offset 4200−4096 = 104 → 34K+104 = 34920. Stack crece negativo: virtual 15 KB → offset crudo 3 KB − 4 KB = −1 KB → 28K−1K = 27 KB. Selección de segmento con los bits altos: Seg = (VA & SEG_MASK) >> SEG_SHIFT, Offset = VA & OFFSET_MASK, si Offset ≥ Bounds → fault.

Cap. 17 · Espacio libre resuelto

Heap de 30 bytes: 10 libres, 10 usados, 10 libres → 2 nodos en la lista (splitting/coalescing). Heap de 4096 de mmap: un nodo con size = 4096 − sizeof(node_t). El header guarda size+magic y free usa (header_t*)ptr − 1; pedir N reserva N + header. Libres 10, 30, 20 y pedido de 15: best → 20 (resto 5); worst → 30 (resto 15); first → 30.

Cap. 18 · Paginación lineal resuelto

Espacio de 64 B, páginas de 16 B, 8 frames. Tabla VP0→PF3, VP1→PF7, VP2→PF5, VP3→PF2. Virtual 21 = 010101 → VPN 01, offset 0101; VP1→PF7 (111) → 1110101 = 117. Tabla lineal de 32 bits con 4 KB: 220 PTE × 4 B = 4 MB por proceso. El pseudocódigo de traducción y el trace de un loop muestran las referencias extra a la tabla.

Cap. 19 · TLB resuelto

Arreglo de 10 ints (4 B), páginas de 16 B: patrón miss, hit, hit, miss, hit, hit, hit, miss, hit, hit = 70 % de hit rate (localidad espacial). Repetir el recorrido mejora por localidad temporal. LRU en loop de n+1 páginas con TLB de n → 0 % de hits. Flush vs ASID en el context switch. MIPS R4000: VPN 19 bits, ASID 8 bits, TLB por software.

→ Práctico Ej. 10, 11

Cap. 20 · Tablas chicas resuelto

Páginas de 16 KB: 18 bits de VPN → 1 MB por tabla (4× menos, pero fragmentación interna). Multinivel: espacio de 16 KB, páginas de 64 B → VPN de 8 bits, tabla lineal de 1 KB = 16 páginas de tabla de 16 PTE, directorio de 16 entradas (4 bits). Solo 3 páginas (1 directorio + 2 tablas) en lugar de 16. Traducción de 0x3F80: PD index 1111 (15) → PT index 1110 (14) → PFN 55 → (55<<6)+0 = 0x0DC0. Tres niveles: espacio de 30 bits, páginas de 512 B → 128 PTEs por página → 7 bits por nivel: (7,7,7,9). Costo: 2 accesos extra en un TLB miss.

→ Práctico Ej. 13, 14, 15

tarea paging-multilevel-translate.py y comparar tamaño de tabla lineal vs multinivel.
Cap. 21 · Swapping resuelto

Present bit; page fault = acceso legal a una página no presente. Handler: buscar frame libre → si no hay, EvictPage() → DiskRead (proceso blocked) → present=1, PFN → reintentar. Tres casos en un TLB miss: válida y presente / válida no presente / inválida. Watermarks HW/LW con un daemon en background y clustering de escrituras. Cap. 22 ★ · Políticas de reemplazo resuelto

AMAT = TM + Pmiss·TD. Con TM=100 ns, TD=10 ms: Pmiss=0,1 → ≈ 1 ms; Pmiss=0,001 → ≈ 10,1 µs.
Traza 0,1,2,0,1,3,0,3,1,2,1 con 3 frames: OPT 6 hits/5 misses = 54,5 % (los 3 primeros son compulsory); FIFO 36,4 %; LRU iguala a OPT.
Belady con FIFO: 1,2,3,4,1,2,5,1,2,3,4,5 empeora al pasar de 3 a 4 frames (LRU tiene stack property).
Workloads: sin localidad (todas iguales), 80-20 (LRU mejor), looping secuencial de 50 páginas (LRU y FIFO 0 % incluso con 49 frames; Random mejor).
Reloj: use bit, la aguja limpia bits en 1 hasta encontrar uno en 0; se prefiere víctima clean antes que dirty.

→ Práctico Ej. 19(b); muy probable en V/F

Con 3 frames son 9 faults; con 4 frames son 10 faults.

Cap. 23 · VAX/VMS y Linux resuelto

VAX: páginas de 512 B → VPN de 23 bits; dos bits altos eligen segmento (P0, P1, S). Página 0 inaccesible (null pointer), kernel mapeado en cada address space. Sin reference bit → se emula con permisos y un trap. Segmented FIFO (RSS por proceso) + listas de segunda oportunidad (clean/dirty) + clustering. Lazy: demand zeroing y COW (read-only en ambos; al escribir, trap y copia). Linux: corte user/kernel en 0xC0000000 (32 bits), kernel logical (kmalloc, mapeo directo, no swappable, apto DMA) vs virtual (vmalloc); 4 niveles con 36 bits de traducción; huge pages 2 MB/1 GB; page cache con 2Q (inactive/active); mmap; NX, ROP, ASLR/KASLR; Meltdown/Spectre y KPTI.
